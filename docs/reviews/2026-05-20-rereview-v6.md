## Executive Summary

The 20 fixes addressed real problems and the code quality of individual implementations is solid. However, the score only improves by 1.0 because **the majority of new capabilities are standalone classes that aren't wired into the actual capture pipeline**. A camera app is judged by what reaches the sensor and the saved JPEG — not by the existence of utility classes. Six new files were created (ZslRingBuffer, SemanticMeteringEngine, VideoStabilizer, TemporalDenoiser, PortraitLighting, CropSuggestionEngine) but none of them have callers. None of them have tests. A world-class camera team would never ship code with no integration and no tests.

## What Improved (Genuinely)

### 1. Settings Deterministically Reach Hardware (+2)
The `forceSemiAuto` logic in CameraViewModel correctly forces `CONTROL_AE_MODE_OFF` with manual ISO/shutter when a CaptureRecipe is active. This was the #1 problem and it's properly fixed. The Camera2SettingsApplier's semi-auto path clamps ISO and exposure to hardware ranges.

### 2. Weighted "Shoot Now" Scoring (+1.5)
Replacing boolean AND with weighted 0–1.0 scoring is a significant improvement. The exclusion of BACKLIT/MIXED scenes (which need coaching, not shoot-now) and PRO/TRUE_SCENE presets shows thoughtful design. Tests pass.

### 3. Tiered Explainer per UserTier (+1.5)
Excellent design. EVERYDAY users see "Cleaned up grain", PRO users see "Bilateral NR, YCbCr domain". The `headlineForTier()` and `stageLabelsForTier()` approach is clean and extensible. This is how Apple does it.

### 4. Skin Tone Fidelity (+1)
The `SkinToneCategory` enum with 6 categories and Lab-space correction with ΔE < 2.0 target is the right approach. Using YCbCr detection → Lab correction is better than the old hue-rotation hack.

### 5. Edge-Aware Sharpening (+0.5)
Sobel gradient-magnitude edge mask to suppress sharpening at strong edges prevents halos. Correct approach.

### 6. Linear-Light LUT Pipeline (+0.5)
Bracketing 3D LUT application with sRGB→linear→LUT→linear→sRGB is correct color science.

### 7. Audio Shutter with Ringer Respect (+0.5)
`MediaActionSound.SHUTTER_CLICK` with `RINGER_MODE_SILENT` check is exactly right.

### 8. Coaching Behavior Tracking (+0.5)
`dismissedHintTypes` and `onCaptured(wasCoached)` allow coaching fatigue detection.

## Top 20 Remaining Critical Issues (Priority Order)

### 1. NEW FILES NOT INTEGRATED INTO CAPTURE FLOW (Severity: CRITICAL)
**The single biggest problem.** Six new files exist as standalone classes with zero callers:
- `ZslRingBuffer` — never populated, never queried
- `SemanticMeteringEngine` — never called from FrameAnalysisPipeline or CameraViewModel
- `VideoStabilizer` — never called from any video capture path
- `TemporalDenoiser` — never called from any video processing path
- `PortraitLighting` — never called from CaptureManager.saveProcessedCopy()
- `CropSuggestionEngine` — never called from review UI

**Impact:** These features literally don't exist from the user's perspective. A Pixel/iPhone ships nothing without integration tests proving the feature works end-to-end.

### 2. ZERO TESTS FOR 6 NEW FILES (Severity: CRITICAL)
None of the new files have any test coverage:
- ZslRingBuffer: Ring buffer logic, capacity wraparound, getBestFrame selection
- VideoStabilizer: Trajectory smoothing, gyro→transform conversion
- TemporalDenoiser: Motion detection, temporal blending, ISO-adaptive strength
- PortraitLighting: Mask-based relighting, edge handling
- CropSuggestionEngine: Ratio calculations, face containment, scoring
- SemanticMeteringEngine: Zone-based metering, EV compensation calculation

**Impact:** No confidence these implementations are correct.

### 3. CaptureManager HAS NO TESTS (Severity: HIGH)
CaptureManager is the most critical file in the app — it orchestrates the entire capture pipeline. It has zero test coverage. Key untested paths:
- `captureSmartPhoto` with all parameter combinations
- `captureHdrBracket` and `captureHdrBracket5Frame` return values
- `saveProcessedCopy` processing chain (NR → enhance → tone → sharpen → depth)
- Macro focus sweep distance calculations
- Error handling for all IO paths

### 4. `isHintFatigued()` IS DEAD CODE (Severity: MEDIUM)
The `isHintFatigued(hintKey)` method is defined but never called in `generateCoaching()`. The coaching engine tracks dismissals but never actually suppresses fatigued hints.

**Fix:** Add `if (isHintFatigued(hint.text.take(20))) hint = null` before returning hints.

### 5. `srgbToLinearLut` QUANTIZES TO 8-BIT (Severity: MEDIUM)
The linear-light conversion LUTs map 8-bit input to 8-bit output:
```kotlin
private val srgbToLinearLut = IntArray(256) { i ->
    val linear = ...
    (linear * 255.0).roundToInt().coerceIn(0, 255)  // <-- 8-bit quantization
}
```
This loses precision in the darks where sRGB→linear compression is steepest. Values 0–12 in sRGB all map to 0 in linear. A Float LUT (or 16-bit) would preserve shadow gradients.

**Impact:** Banding in dark tones when LUT is applied.

### 6. HIGHLIGHT CLIPPING NOT SHOWN IN VIEWFINDER (Severity: MEDIUM)
`ExposureAnalysis.computeHighlightClipping()` exists but ViewfinderScreen never calls it. There's no zebra stripe overlay, no blinking highlights, no red warning. The function computes the data but it's never surfaced.

### 7. `dismissedHintTypes` KEY IS FRAGILE (Severity: LOW-MEDIUM)
Using `lastHint?.text?.take(20)` as the key for hint fatigue tracking means any text change breaks the tracking. A structured enum key would be more robust.

### 8. PORTRAIT LIGHTING IS MASK-ONLY, NO DEPTH (Severity: MEDIUM)
`PortraitLighting.apply()` accepts a `depthMap` parameter but never uses it. Studio lighting should use depth to create realistic light falloff. Contour mode should use depth for shadow direction. Currently it's just mask-based brightness adjustment.

### 9. TEMPORAL DENOISER HAS NO ALIGNMENT (Severity: MEDIUM)
`TemporalDenoiser.processFrame()` blends current frame with accumulated frame without any motion compensation/alignment. Even slight camera movement between frames will blur details. Needs TileAligner integration before temporal blending.

### 10. VIDEO STABILIZER NOT CONNECTED TO GYRO (Severity: HIGH)
`VideoStabilizer.estimateTransformFromGyro()` takes gyro values, but there's no code reading gyro data during video recording and feeding it to the stabilizer. The existing `LevelSensor` reads accelerometer/gyro but isn't connected to VideoStabilizer.

### 11. `computeEdgeMask` ONLY AT PYRAMID LEVEL 0 (Severity: LOW)
LaplacianSharpener computes edge mask only for the fine level. Mid and coarse levels get uniform sharpening, which can still create halos at large-scale edges.

### 12. MIXED LIGHTING WB NOT USED IN CAPTURE (Severity: MEDIUM)
`ColorTemperatureEstimator.estimateMixedLighting()` detects mixed lighting but the result never feeds into Camera2SettingsApplier or the processing pipeline. No per-region WB correction happens.

### 13. CROP SUGGESTIONS NOT IN REVIEW UI (Severity: LOW-MEDIUM)
`CropSuggestionEngine.suggest()` computes crops but SmartReviewOverlay and AiExplainerOverlay don't display them. No UI for the user to see or apply suggested crops.

### 14. DepthEstimator HIGH-RES REUSES SAME MODEL (Severity: MEDIUM)
`estimateDepthHighRes()` calls the 256×256 TFLite model with a 512×512 input. TFLite models have fixed input dimensions — this will either crash or silently resize to 256×256 internally. A separate 512×512 model file is needed, or the input must be tiled.

### 15. ZSL RING BUFFER STORES JPEG BYTES (Severity: MEDIUM)
`ZslFrame` stores `jpegBytes: ByteArray` which means each frame is JPEG-compressed. For ZSL to work properly, raw/YUV frames should be stored to avoid double-compression artifacts. JPEG encoding also adds latency to each ring buffer push.

### 16. SEMANTIC METERING MASK INDEXING BUG (Severity: HIGH)
In `SemanticMeteringEngine.computeSemanticMetering()`:
```kotlin
val maskIdx = if (it.size == pixels.size) idx
else (sy * it.size / (sw * sh)).coerceIn(0, it.size - 1)
```
The else branch computes a 1D index from `sy` only, ignoring `sx`. This means all pixels in the same row sample the same mask value, producing horizontal banding in the metering.

### 17. NO EXIF WRITING (Severity: MEDIUM)
The capture pipeline saves JPEGs but there's no EXIF metadata writing. No GPS, no camera model, no ISO/shutter speed in EXIF, no orientation tag. Every photo viewer and editor relies on EXIF.

### 18. NO ORIENTATION HANDLING (Severity: MEDIUM)
No rotation based on device orientation at capture time. Photos taken in landscape will display rotated in gallery apps without EXIF orientation.

### 19. CameraViewModel IS 1200+ LINES (Severity: LOW-MEDIUM)
The ViewModel is a god object handling: camera lifecycle, capture orchestration, AI pipeline results, UI state, face tracking, settings application, and review screen data. This should be split into focused use-cases.

### 20. NO BURST MODE UI (Severity: LOW)
CoachingEngine suggests "hold shutter for burst" with `CoachingAction.EnableBurst`, but there's no burst capture implementation. Long-press on ShutterButton calls `onLongPressStart()` but the ViewModel's handler for this is not visible in the code.
